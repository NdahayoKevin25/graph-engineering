Use the audited engine renderer for `authentication.oauth`; do not execute this document as a script. Apply `authentication.jwt` (normally through `authentication.password`) first, and provide an application-owned `src/services/oauthAccountDirectory.ts` exporting `findAccountByEmail(email): Promise<{ id: string; emailVerified: boolean } | null>` and `createAccountForVerifiedEmail(email): Promise<{ id: string }>`. Created accounts must be marked email-verified so `resolveAuthenticationIdentity` accepts them. Choose `providers`, the exact `postLoginRedirects` allowlist and, for `oidc`, its static HTTPS issuer, endpoints and `jwksUri` (the provider's published signing keys, used to verify ID token signatures). Register `<OAUTH_REDIRECT_BASE_URL>/api/auth/oauth/<provider>/callback` with each provider and set the client id/secret variables in the deployment environment; the renderer never writes their values.
