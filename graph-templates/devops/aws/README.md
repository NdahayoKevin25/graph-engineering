# devops.aws — ECS Express Mode request descriptor

- **What:** Proposes `deploy/ecs-express-create-service.json`, a local JSON request matching the AWS ECS `CreateExpressGatewayService` API. Generation makes no AWS, Docker, deployment, provisioning or network call.
- **When:** Use after `devops.docker` when an operator has built and pushed that reviewed image to a private ECR repository and obtained its sha256 image digest. This node does not build, push or discover the image.
- **Requires:** The target `Dockerfile` must exactly match the reviewed `devops.docker` Node 24 file for the selected port. The catalog test pins both template copies to the same bytes; a canonical Dockerfile change requires re-review of this node. The application in the image must listen on that port and return HTTP 200 at `/`, the reference `project.node-express` health route. The renderer cannot inspect the pushed image or prove the digest came from this Dockerfile.
- **Configure via:** Provide a service name, same-account private ECR digest URI, explicit port, three distinct IAM role ARNs, two or more distinct subnet IDs, one or more security group IDs, and an explicit `secrets` array (empty if none). Secret entries use full Secrets Manager or SSM Parameter Store ARNs. `acknowledgeUnverifiedAwsPrerequisites: true` explicitly acknowledges that these external prerequisites and any future deployment remain unverified here; it is not evidence they passed.
- **Produces:** Only the local request JSON. It contains no `environment` plaintext values, command override, repository credentials, IAM policy, deploy script, or automatic AWS operation. An existing custom descriptor is not overwritten; identical output is a no-op.
- **Connects to:** ECS Express Mode uses the execution role to pull ECR images and retrieve secrets, the infrastructure role to provision its load balancer/network/scaling resources, and the task role for application AWS API calls. The roles must be provisioned separately with correct trust and least privilege. This reviewed descriptor requires secret ARNs in the ECR image's account and Region; an operator must choose that Region for any later API call. The supplied VPC IDs must be checked for region, VPC, availability-zone spread, routes, ingress and egress. The renderer checks only syntax and the described account/Region relationships.
- **Test:** `npm run test -w @graph-engineering/engine -- tests/template-runtime-aws.test.ts` from the Graph Engineering repository root. These are local renderer and privacy tests; they do not exercise an AWS account or prove IAM, network reachability, image provenance or runtime health.
- **Validate:** Review the JSON, exact Dockerfile and selected port, image digest provenance, pre-existing IAM roles, VPC IDs, secret ARN permissions, health response and expected AWS charges before any separate operator-initiated API invocation. Executing `CreateExpressGatewayService` provisions chargeable AWS resources; this template never invokes it. Keep the generated request private: the engine excludes this exact descriptor path from cloud context export even with `exportPaths: ["**"]` and refuses to publish a repository containing it.
- **Security:** Secret values are never accepted as inputs; only full `arn:aws:secretsmanager:...:secret:...` or `arn:aws:ssm:...:parameter/...` references are emitted. Commercial `aws` partition and same-account private ECR are the reviewed scope; cross-account, GovCloud and China require a separate audited implementation.

AWS references: [CreateExpressGatewayService request and role semantics](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_CreateExpressGatewayService.html), [container image and port fields](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_ExpressGatewayContainer.html), [ARN secret references](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_Secret.html), and [network defaults](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_ExpressGatewayServiceNetworkConfiguration.html).
